## 2. 终端用户支付全流程（含无感容错）

```mermaid
flowchart TD
    Start[用户发起支付请求] --> Route{路由引擎<br/>选择通道 A}
    
    Route --> AuthCheck{用户已授权<br/>通道 A？}
    
    AuthCheck -->|已授权| CallA[调用通道 A 支付]
    AuthCheck -->|未授权| CompAuth[综合授权弹窗<br/>一次性授权所有通道]
    
    CompAuth --> StoreAuth[存储各通道授权<br/>记录绑定关系]
    StoreAuth --> CallA
    
    CallA --> SuccessA{通道 A<br/>支付成功？}
    
    SuccessA -->|成功| RecordBind[记录渠道绑定<br/>返回支付成功]
    SuccessA -->|失败/异常| Fallback{通道 A 不可用<br/>触发容错}
    
    Fallback --> RouteNext{路由引擎<br/>选择备选通道 B}
    
    RouteNext --> AuthCheckB{用户已授权<br/>通道 B？}
    
    AuthCheckB -->|已授权<br/>综合授权已涵盖| CallB[无感调用通道 B]
    AuthCheckB -->|未授权| ReAuth[引导用户补充授权<br/>或根据策略决定]
    
    ReAuth --> AuthBDone{授权完成？}
    AuthBDone -->|完成| CallB
    AuthBDone -->|拒绝/失败| PayFail[返回支付失败]
    
    CallB --> SuccessB{通道 B<br/>支付成功？}
    
    SuccessB -->|成功| RecordBindB[记录渠道 B 绑定<br/>返回支付成功]
    SuccessB -->|失败| MoreFallback{还有候选通道？}
    
    MoreFallback -->|有| RouteNext
    MoreFallback -->|无| PayFail
```

## 3. 退款流程

```mermaid
flowchart TD
    RefundReq[退款请求] --> QueryTrade[查询原始交易记录]
    QueryTrade --> GetChannel[获取原始支付通道<br/>记录的渠道绑定]
    GetChannel --> RefundRoute{优先走<br/>原始通道退款}
    
    RefundRoute -->|原始通道可用| CallRefund[调用原始通道<br/>退款 API]
    RefundRoute -->|原始通道不可用| FallbackRefund[尝试其他已授权<br/>通道退款]
    
    CallRefund --> RefSuccess{退款成功？}
    FallbackRefund --> RefSuccess
    
    RefSuccess -->|成功| RefDone[记录退款完成<br/>返回成功]
    RefSuccess -->|失败| RefFail[返回退款失败]
```

## 4. 对账流程

```mermaid
flowchart TD
    DailyTrigger{每日定时<br/>触发对账} --> FetchTrades[遍历所有<br/>交易记录]
    FetchTrades --> ForEach{遍历每笔<br/>交易}
    ForEach --> CallQuery[调用对应通道<br/>的查询 API]
    CallQuery --> Compare[比较平台记录<br/>与第三方记录]
    Compare --> Match{匹配？}
    
    Match -->|一致| RecordMatch[标记对账成功<br/>更新记录]
    Match -->|不一致| RecordDiff[标记差异<br/>生成差异报告]
    
    RecordDiff --> NextTrade{还有未处理<br/>交易？}
    RecordMatch --> NextTrade
    
    NextTrade -->|有| ForEach
    NextTrade -->|无| GenReport[生成对账报告<br/>推送给商户]
```

## 6. 策略配置流程

```mermaid
flowchart TD
    StrategyStart[进入策略配置<br/>页面] --> AddRule[添加策略规则<br/>priority/condition/channels]
    AddRule --> SetCondition[设置条件<br/>金额区间/场景/地域/设备]

```

## 流程说明

### 6.1 商户接入
1. 商户在平台注册并完成实名认证
2. 创建支付应用，获得唯一 `appid`
3. 从可用支付通道列表中选择需要接入的通道（可多选）
4. 为每个选中的通道配置具体实例：密钥、第三方商户号、费率、额度限制等
5. 配置支付策略：定义多条规则，每条规则关联条件和候选通道列表
6. 发布策略后，应用正式上线，开始接收支付请求

### 6.2 用户支付（核心）
1. 用户在商户应用下发起支付请求
2. 路由引擎根据已发布的策略，匹配最优规则，选择候选通道列表中的最佳通道 A
3. 检查用户是否已对通道 A 授权
4. 若已授权：直接调用通道 A 执行支付
5. 若未授权：引导用户进行「综合授权」，一次性取得所有候选通道的授权
6. 支付成功后，记录渠道绑定关系（用户-应用-通道）
7. 若通道 A 不可用：触发容错，路由引擎从候选列表中选择下一个通道 B
8. 检查用户是否已对通道 B 授权（若已执行综合授权，则已涵盖）
9. 若已授权：无感切换，调用通道 B
10. 若未授权：根据策略的 `fallback_policy` 决定是否需要用户再次授权
11. 循环尝试直至支付成功或所有候选通道耗尽

### 6.3 综合授权优势
- 用户仅需在首次支付时完成一次授权操作
- 后续任何通道切换均无需用户感知
- 降低支付失败率，提升用户体验
- 商户无需为每个通道单独开发授权流程

### 6.4 容错策略等级

| 等级 | 配置 | 行为 |
|------|------|------|
| **无感模式** | `require_re_authorization: false` | 所有候选通道均已预授权，切换完全无感 |
| **降级提示** | `require_re_authorization: true` | 备用通道未授权时，提示用户快速授权 |
| **终止模式** | `fallback: disabled` | 原通道失败即终止，不尝试备用 |
