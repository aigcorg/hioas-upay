# 时序图 (Sequence Diagrams)

## 1. 支付全流程时序图（含综合授权 + 容错切换）

```mermaid
sequenceDiagram
    participant User as 终端用户
    participant Merchant as 商户应用
    participant API as 平台 API Gateway
    participant Router as 路由引擎
    participant Auth as 授权管理服务
    participant StrategyDB as 策略数据库
    participant ChannelA as 通道 A 适配器
    participant ChannelB as 通道 B 适配器
    participant ThirdA as 第三方通道 A
    participant ThirdB as 第三方通道 B

    User->>Merchant: 选择商品，点击支付
    Merchant->>API: POST /pay/order/create (订单创建请求)
    API->>Router: 路由请求，获取策略
    
    Router->>StrategyDB: 查询应用策略规则
    StrategyDB-->>Router: 返回候选通道列表 [A, B, C]
    
    Router->>Auth: 检查用户对通道 A 的授权状态
    Auth-->>Router: 未授权（首次支付）
    
    Router-->>API: 返回需要授权
    API-->>Merchant: 返回授权提示
    Merchant-->>User: 弹出综合授权弹窗
    
    User->>Merchant: 确认授权（全选）
    Merchant->>API: POST /auth/comprehensive (综合授权请求)
    API->>Auth: 发起综合授权流程
    
    Auth->>ChannelA: 调用通道 A 获取授权
    ChannelA->>ThirdA: 请求授权Token
    ThirdA-->>ChannelA: 返回授权凭证
    ChannelA-->>Auth: 授权成功
    
    Auth->>ChannelB: 调用通道 B 获取授权
    ChannelB->>ThirdB: 请求授权Token
    ThirdB-->>ChannelB: 返回授权凭证
    ChannelB-->>Auth: 授权成功
    
    Auth->>Auth: 记录用户-应用-各通道绑定关系
    Auth-->>API: 综合授权完成
    API-->>Merchant: 返回授权成功
    Merchant-->>User: 授权完成，继续支付
    
    Merchant->>API: POST /pay/order/create (重新请求支付)
    API->>Router: 路由请求
    
    Router->>StrategyDB: 查询策略
    StrategyDB-->>Router: 返回候选通道 [A, B, C]
    
    Router->>Auth: 检查用户对通道 A 的授权
    Auth-->>Router: 已授权 ✅（综合授权已记录）
    
    Router->>ChannelA: 调用通道 A 执行支付
    ChannelA->>ThirdA: POST /pay (第三方支付请求)
    
    Note over ThirdA: 通道 A 异常/超时/失败
    ThirdA-->>ChannelA: 支付失败 / 超时
    
    ChannelA-->>Router: 通道 A 不可用
    
    Router->>Auth: 检查用户对通道 B 的授权
    Auth-->>Router: 已授权 ✅（综合授权已记录，无感！）
    
    Note over Router: 容错切换 → 通道 B，用户无感知
    
    Router->>ChannelB: 调用通道 B 执行支付
    ChannelB->>ThirdB: POST /pay (第三方支付请求)
    ThirdB-->>ChannelB: 支付成功
    ChannelB-->>Router: 支付成功
    
    Router->>Router: 记录渠道绑定（User ↔ 通道 B）
    Router-->>API: 支付成功结果
    API-->>Merchant: 返回支付成功
    Merchant-->>User: 展示支付成功页面
```

## 3. 退款时序图

```mermaid
sequenceDiagram
    participant Merchant as 商户应用
    participant API as 平台 API
    participant Trade as 交易管理服务
    participant Router as 路由引擎
    participant ChannelOrig as 原始通道适配器
    participant ThirdOrig as 第三方原始通道
    participant ChannelAlt as 备选通道适配器
    participant ThirdAlt as 第三方备选通道

    Merchant->>API: POST /pay/refund (退款请求)
    API->>Trade: 查询原始交易记录
    Trade-->>API: 返回原始通道 = 通道 A
    
    API->>Router: 退款路由决策
    
    Router->>ChannelOrig: 调用原始通道退款
    ChannelOrig->>ThirdOrig: POST /refund (第三方退款请求)
    
    Note over ThirdOrig: 原始通道异常/不支持退款
    ThirdOrig-->>ChannelOrig: 退款失败 / 异常
    
    ChannelOrig-->>Router: 原始通道退款失败
    
    Router->>Trade: 查询用户对备选通道 B 的授权
    Trade-->>Router: 已授权 ✅
    
    Note over Router: 尝试备选通道 B 退款
    Router->>ChannelAlt: 调用备选通道退款
    ChannelAlt->>ThirdAlt: POST /refund (第三方退款请求)
    ThirdAlt-->>ChannelAlt: 退款成功
    ChannelAlt-->>Router: 退款成功
    
    Router-->>API: 退款成功
    API-->>Merchant: 返回退款成功结果
```

## 4. 回调处理时序图

```mermaid
sequenceDiagram
    participant Third as 第三方支付通道
    participant Callback as 回调接收服务
    participant Verify as 签名验证
    participant Trade as 交易管理服务
    participant MerchantCB as 商户回调服务

    Third->>Callback: HTTP POST /callback (支付结果通知)
    
    Callback->>Verify: 验证回调签名
    Verify-->>Callback: 签名验证通过 ✅
    
    Callback->>Trade: 更新交易状态
    Trade->>Trade: 修改订单状态为"支付成功"
    Trade-->>Callback: 更新完成
    
    Note over Callback: 是否需要转发给商户？
    Callback->>MerchantCB: HTTP POST (转发回调通知，可选)
    MerchantCB-->>Callback: 处理完成 ACK
    
    Callback->>Third: 返回 success 应答
```

## 5. 策略发布时序图

```mermaid
sequenceDiagram
    participant Admin as 商户管理员
    participant H5 as 商户后台 H5
    participant API as 平台 API
    participant StrategySvc as 策略管理服务
    participant DB as 策略数据库
    participant Router as 路由引擎

    Admin->>H5: 在策略配置页面填写规则
    H5->>API: POST /strategy/draft (保存草稿)
    API->>StrategySvc: 保存策略草稿
    StrategySvc->>DB: 存储草稿
    DB-->>StrategySvc: 保存成功
    StrategySvc-->>API: 返回草稿ID
    API-->>H5: 返回保存成功
    H5-->>Admin: 提示保存成功
    
    Admin->>H5: 点击「发布策略」
    H5->>API: POST /strategy/publish (发布策略)
    API->>StrategySvc: 发布策略
    
    StrategySvc->>DB: 将草稿状态改为"已发布"
    StrategySvc->>DB: 旧策略标记为"已失效"
    DB-->>StrategySvc: 更新完成
    
    StrategySvc->>Router: 通知策略变更（事件/消息）
    Router->>Router: 刷新策略缓存
    
    StrategySvc-->>API: 发布成功
    API-->>H5: 返回发布成功
    H5-->>Admin: 提示策略已生效
```

## 6. 通道健康检查时序图

```mermaid
sequenceDiagram
    participant Monitor as 健康监控服务
    participant ChannelA as 通道 A 适配器
    participant ThirdA as 第三方通道 A

    Note over Monitor: 定时触发（如每 30 秒）
    Monitor->>ChannelA: getHealth() 
    ChannelA->>ThirdA: 发送心跳/测试请求
    ThirdA-->>ChannelA: 响应正常（200 OK / 特有响应）
    ChannelA-->>Monitor: ChannelHealth{status: HEALTHY, latency: 120ms}
    
    Note over Monitor: 定时触发
    Monitor->>ChannelB: getHealth()
    ChannelB->>ThirdB: 发送心跳/测试请求
    
    Note over ThirdB: 响应慢/超时
    ThirdB-->>ChannelB: 超时 / 500错误
    ChannelB-->>Monitor: ChannelHealth{status: DEGRADED, latency: 3000ms}
    
    Monitor->>Monitor: 更新通道状态（供路由引擎参考）
    Note over Monitor: 路由引擎将 DEGRADED 通道降低优先级
```

## 时序图说明

### 关键交互点

| 环节 | 说明 |
|------|------|
| **综合授权** | 用户首次支付时弹窗，一次性取得所有候选通道的授权凭证，后续切换完全无感 |
| **容错切换** | 通道 A 不可用时，路由引擎自动选择通道 B；因已综合授权，用户无需再次操作 |
| **渠道绑定** | 每次支付成功后，记录用户-应用-通道的绑定关系，退款时优先走同一通道 |
| **回调处理** | 第三方异步通知，经过签名验证后更新交易状态，可选转发给商户 |

### 设计意图

- **用户无感**：通过综合授权，将通道切换的复杂性屏蔽在用户视野之外
- **可用性优先**：路由引擎结合策略规则 + 实时通道健康状态，选择最优通道
- **可扩展**：适配器模式使得新通道接入只需实现接口 + 配置，不需要修改核心逻辑
