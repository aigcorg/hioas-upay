# 🎯 项目概述

**项目名称**：PayHub — 多通道支付聚合平台  
**一句话定位**：让商户通过一个统一接口接入微信、支付宝、中金支付、宝付支付等多个支付通道，按策略自动路由，通道异常时自动无感切换。

**核心价值主张**：
- 商户只需对接本平台一个 API，即可使用所有已接入的第三方支付通道
- 智能策略路由：根据金额、费率、场景、风控动态选择最佳通道
- 用户一次授权所有通道，后续通道切换零感知
- 新支付通道接入仅需配置，无需代码开发

**目标用户**：
- 初阶：中小商户（电商、服务平台、直播等）——希望快速接入支付，不懂技术
- 高阶：大型 SaaS 平台、支付中台——希望统一管理多个支付通道，优化费率和成功率

**设计原则**：
- 低技术门槛：所有配置项都可视化，表单向导式设置
- 透明可控：商户能看到每笔交易走哪个通道、成功率、费率收益
- 可扩展：新通道插件化接入，后台开启即可用

# 🧭 用户角色与权限

## 角色 1：商户管理员（Merchant Admin）

**能做什么**：
- 注册账号、提交认证材料
- 创建/管理支付应用（获得 appid）
- 从可用通道列表中选择要接入的支付通道
- 为每个通道配置密钥、费率、额度等参数
- 创建和发布支付策略（规则优先级、候选通道、容错设置）
- 查看交易记录、对账报告、统计数据
- 查看通道健康状态、修改配置

**不可以做什么**：
- 无法直接调用第三方支付 API（由平台代为调用）
- 无法修改平台侧的通道元信息（只能配置自己应用下的实例）

---

## 角色 2：终端用户（End User / Payer）

**能做什么**：
- 在商户应用中发起支付
- 首次支付时完成「综合授权」（一次性授权该应用下的所有支付通道）
- 看到支付成功/失败结果
- 发起退款请求（通过商户应用）

**无感知设计**：
- 通道切换完全对用户透明
- 不需要为每个通道单独授权
- 不需要知道底层用的是微信还是支付宝

---

## 角色 3：平台管理员（Platform Admin）

**能做什么**：
- 审核商户注册和认证申请
- 在平台侧添加/启用/停用新的支付通道（元信息配置）
- 管理系统全局配置（容错策略、健康检查间隔等）
- 查看全局交易统计、结算数据
- 处理对账差异（人工复核）

# 🖥️ 界面模块清单

## 模块 A：商户后台（Merchant Dashboard）

### A1. 登录 / 注册页
- 简洁的注册表单：公司名称、统一社会信用代码、联系人、手机、邮箱
- 登录页：手机号 + 密码 or 邮箱 + 密码
- 未认证状态提示：「完成实名认证后即可创建应用」

### A2. 认证材料上传页
- 卡片式上传区域：营业执照正面/反面、法人身份证正面/反面、授权书
- 拖拽上传 or 点击上传，支持预览
- 提交后状态变更为「认证中」，可在列表中查看审核进度

### A3. 应用管理页（核心）
- 应用列表卡片：应用名称、appid、状态（草稿/启用/停用）、创建时间
- 创建应用弹窗/向导：
  - 步骤 1：应用名称、类型（电商/服务/直播/其他）、回调地址
  - 步骤 2：确认 → 生成 appid 和 secret_key（仅显示一次，提示保存）

### A4. 通道管理页（应用下的子页面）
- 可用通道列表（平台提供的）：
  - 卡片展示：通道图标/名称、支持的场景（电商、直播、APP 等）、状态（可用/不可用）
  - 勾选框选择，底部「确认选择」按钮
- 已选通道列表：
  - 每个通道卡片显示：状态（未配置/已配置/测试中/正常/异常）、最近测试结果
  - 点击卡片进入配置表单
- 通道配置表单（动态生成，根据通道不同）：
  - 微信 JSAPI：appid、mch_id、secret（加密输入框）、证书路径、key 路径、费率、单笔限额、日限额
  - 支付宝网站支付：app_id、商家私钥（加密）、支付宝公钥、费率...
  - 中金支付、宝付支付：按各自字段配置
- 「测试连通性」按钮：调用测试 API，显示结果（成功/失败及错误信息）

### A5. 策略配置页（应用下的子页面）
- 策略列表：策略名、状态（草稿/已发布/已失效）、版本、创建时间
- 新建策略向导（分步表单）：
  - **步骤 1：基本信息** — 策略名称、描述
  - **步骤 2：添加规则**（可添加多条，拖拽排序优先级）：
    - 规则卡片：
      - 优先级数字（1,2,3...），拖拽调整
      - 规则名称
      - 条件设置面板：
        - 金额区间：滑块 or 两个输入框（最小值、最大值，可留空表示无穷）
        - 场景选择：多选下拉（电商、直播、APP、H5...）
        - 地域：下拉选择（可选）
        - 设备类型：多选（移动端、PC 端）
        - 风控等级：单选（正常、低风险、中风险、高风险）
      - 候选通道选择：从已配置的通道实例中多选
      - 排序方式：单选（费率最低优先、费率最高优先、额度优先、延迟最低优先）
      - 「删除规则」按钮
    - 「添加新规则」按钮
  - **步骤 3：容错策略设置**：
    - 开关：是否启用自动容错
    - 数字输入：最大尝试次数（1-5）
    - 单选：备用通道不可用时是否需要用户重新授权（是/否 — 推荐默认否，即无感模式）
    - 说明文字：「如果选择『不需要重新授权』，用户需在首次支付时完成综合授权」
  - **步骤 4：预览 & 发布**：
    - 策略预览卡片：以可读的方式显示所有规则和容错策略
    - 发布按钮 → 状态变为已发布，旧策略自动失效

### A6. 交易记录页
- 表格：交易流水号、订单号、金额、状态（待处理/处理中/成功/失败）、使用的通道、创建时间、操作（查看详情、退款）
- 筛选：按日期区间、状态、通道、应用
- 导出按钮（CSV/Excel）

### A7. 对账页面
- 对账任务列表：任务号、日期区间、通道、状态、差异数、完成时间
- 「发起对账」按钮：弹窗选择日期区间、通道（或全通道）
- 点击任务卡片 → 进入详情：
  - 概览：总交易数、匹配数、差异数
  - 差异明细表：订单号、第三方订单号、平台金额、第三方金额、平台状态、第三方状态、差异类型、详情
  - 「下载报告」按钮

### A8. 统计与洞察页（增强体验）
- 仪表板卡片：
  - 今日交易总额、交易笔数
  - 各通道占比环图
  - 各通道成功率条形图
  - 费率收益统计
- 按日/周/月切换时间粒度

## 模块 B：终端用户支付界面（嵌入商户应用或 H5）

### B1. 支付发起页（商户应用内）
- 展示商品/订单信息：名称、金额、商户 logo
- 「支付」按钮（大而明显）
- 点击后调用本平台 API 创建订单

### B2. 综合授权弹窗（首次支付时触发）

**出现时机**：用户第一次在该应用下发起支付，且检测到未对该应用的所有候选通道授权

**弹窗标题**：「你需要授权以下支付方式」or「完成支付方式授权」

**内容**：
- 列表卡片，每张卡片代表一个支付通道：
  - 通道 Logo（微信绿色、支付宝橙色、等）
  - 通道名称：「微信支付」、「支付宝」、「中金支付」、「宝付支付」
  - 简短描述：「用于电商支付」、「支持直播场景」
  - 复选框或开关（全选/部分选择）
- 底部按钮：「确认授权」（主操作）、「取消」（次要）

**交互细节**：
- 用户确认后，平台后台依次向各通道请求授权
- 授权过程中显示加载状态：「正在授权微信支付... 1/3」
- 全部成功 → 弹窗关闭，自动进入支付流程
- 部分成功 → 弹窗提示哪些失败了，允许用户选择忽略失败的通道（「跳过失败的通道，继续支付」or「重新授权」）

**记忆**：一旦综合授权完成，同一用户+同一应用下所有后续支付都不再弹出此窗

### B2b. 支付方式选择（如果商户想让用户选择具体通道）
- 支付方式列表（水平滚动 or 网格）：
  - 微信支付（图标）
  - 支付宝（图标）
  - 中金支付（图标）
  - 宝付支付（图标）
- 用户点击其中一个 → 调用本平台 API，平台根据策略判断该通道是否可用、用户是否授权
- 如果用户未授权该通道 → 自动触发综合授权流程（或提示快速授权）

> **重要设计决策**：商户可以选择是否展示通道选择 UI。如果不展示，平台完全按策略自动路由，用户体验更流畅；如果展示，用户有选择感，但增加了复杂度。两者均支持。

### B3. 支付结果页
- 成功页：绿色对勚、支付成功字样、订单号、金额、小费提示
- 失败页：红色横幅、失败原因（对用户友好的描述，如「支付渠道暂时不可用，请稍后重试」）、重试按钮、返回商户页按钮

## 模块 C：平台管理后台（Platform Admin）

### C1. 商户审核队列
- 列表：商户名称、公司、状态（待审核/通过/拒绝）、申请时间
- 点击卡片 → 查看详情 + 认证材料预览
- 按钮：「通过」、「拒绝」（弹窗输入理由）

### C2. 通道元信息管理
- 表格：通道编码、名称、适配器类、状态（启用/停用）、支持场景
- 新增通道弹窗：
  - 通道编码（唯一）
  - 通道名称
  - 适配器类全路径（输入框）
  - 支持场景（多选）
  - 配置模板 JSON（编辑器）
  - 「保存」→ 新通道出现在商户可选列表中

### C3. 系统监控页
- 通道健康卡片网格：每个通道一个卡片，显示状态（健康/降级/异常）、延迟、错误率、最近检查时间
- 交易实时监控：每秒交易数、成功率曲线
- 告警日志列表

### C4. 全局配置
- 表单：容错默认开关、默认最大尝试次数、健康检查间隔、对账定时 Cron 表达式

# 🔁 核心交互流程（逐步描述）

## 流程 1：商户从零到上线（全流程）

### Step 1: 注册
1. 用户访问平台，点击「注册」
2. 填写表单（公司名称、统一代码、联系人...）
3. 点击「提交注册」
4. 系统创建账户，跳转到「待认证」提醒页
5. 页面提示：「请上传认证材料以激活账户」

### Step 2: 认证
1. 用户进入「认证」页面
2. 看到 4 个上传区（营业执照正/反、身份证正/反、授权书）
3. 拖拽文件或点击上传，上传过程中显示进度
4. 文件上传完成后可点击预览
5. 点击「提交审核」
6. 状态变为「认证中」，列表中显示预计审核时间
7. 审核结果通过短信/邮件/站内信通知

### Step 3: 创建应用
1. 用户进入「应用管理」页面
2. 点击「创建应用」按钮
3. 弹出创建向导：
   - 输入应用名称（如「电商主站支付」）
   - 选择应用类型（电商/服务/直播/其他）— 单选
   - 输入回调地址（URL 格式校验）
   - 输入同步跳转地址（可选）
4. 点击「下一步」→ 确认页面
5. 点击「创建」→ 显示结果页：
   - 应用 ID
   - **appid**（大字体、高亮、可复制）
   - **secret_key**（大字体、高亮、可复制、一次性显示）
   - 强烈提示：「请立即保存 secret_key，之后无法查看」
6. 用户点击「我已保存，进入应用管理」

### Step 4: 选择支付通道
1. 在应用详情页，看到「支付通道」标签页
2. 默认显示「未选择任何通道」
3. 点击「选择通道」按钮 → 跳转到通道选择页
4. 看到可用通道网格：
   - 每个通道卡片：图标、名称、描述、支持场景标签、右上角状态指示（绿色圆点=可用）
   - 卡片顶部有一个勾选框（未选中时为空心，选中时为实心绿色对勚）
5. 用户勾选需要的通道（例如微信、支付宝、中金支付）
6. 底部出现「确认选择」按钮，旁边显示已选数量
7. 点击确认 → 弹窗确认：「您选择了 3 个通道，是否继续？」
8. 确认 → 页面跳回应用详情，通道列表显示已选 but「未配置」

### Step 5: 配置通道实例
1. 在已选通道列表中，看到每个通道的卡片，状态为「未配置」，卡片上有「配置」按钮
2. 点击「配置」→ 弹出配置表单（Modal）
3. 表单字段根据通道类型动态变化（如微信显示 appid、mch_id、secret 输入框...）
4. 敏感字段（secret、key）使用密码输入框（遮罩），并在输入时显示强度提示
5. 费率字段：百分比输入（如 0.6%），有上下限提示
6. 额度字段：单笔最大金额、日最大金额两个输入框
7. 点击「保存配置」→ 状态变为「已配置，待测试」
8. 配置保存成功后，弹窗提示：「配置已保存，建议测试连通性」

### Step 6: 测试连通性
1. 在实例卡片上，看到「新建配置」按钮变为「测试连通性」按钮
2. 点击测试 → 按钮 loading，「正在测试...」
3. 测试完成后，卡片状态更新：
   - 成功：「正常」（绿色状态指示），显示上次测试时间和延迟
   - 失败：「异常」（红色），显示错误信息，提供「重新测试」和「编辑配置」按钮

### Step 7: 创建支付策略
1. 在应用详情页，切换到「支付策略」标签页
2. 看到空的策略列表 +「新建策略」按钮
3. 点击新建 → 打开策略向导 Modal

**向导步骤 1 — 基本信息**：
- 输入策略名称（如「电商默认策略」）
- 输入描述（可选）
- 点击「下一步」

**向导步骤 2 — 添加规则**：
- 初始状态：显示一条空规则卡片，提示「点击添加规则」
- 点击「添加规则」→ 向导展开一个规则表单面板：
  - 优先级数字显示（1），用户可点击上下箭头改变，或拖拽卡片排序
  - 规则名称输入框（如「低金额微信优先」）
  - **条件面板展开**：
    - 金额区间：两个输入框「最小金额（分）」、「最大金额（分）」，或者选择「不限」的 checkbox
    - 场景：下拉多选（电商、直播、APP、H5...），初始全选
    - 地域：下拉单选（可选，默认不限）
    - 设备类型：复选框组（移动端、PC 端...）默认全选
    - 风控等级：单选 radio（正常/低风险/中风险/高风险），默认正常
  - **候选通道选择面板**：
    - 从已配置的通道实例中选择的多选列表（每个是个带复选框的通道实例卡片）
    - 「全选」/「清空」快捷按钮
    - 至少选择一个，否则底部按钮禁用
  - **排序方式单选**：
    - 「费率最低优先」（默认）
    - 「费率最高优先」
    - 「额度优先」
    - 「延迟最低优先」
  - 点击「保存此规则」→ 卡片折叠，显示规则摘要（优先级、名称、条件简写、通道数、排序方式）
- 用户可以继续点击「添加规则」添加更多规则
- 每个规则卡片顶部有拖拽手柄，用户可以拖动调整优先级顺序
- 每个规则卡片右上角有「删除」和「编辑」按钮
- 向导底部显示「已添加 N 条规则」，右侧有「完成规则设置」按钮

**向导步骤 3 — 容错策略**：
- 开关：「启用自动容错」（默认打开）
- 当开关打开时，显示联动字段：
  - 「最大尝试次数」滑块 or 数字输入（1-5，默认 3）
  - 「备用通道未授权时」单选：
    - 「不需要用户重新授权（无感切换）」（推荐，默认选中）
    - 「需要用户重新授权」
  - 旁边有提示文字：「选择『不需要重新授权』意味着用户需在首次支付时完成所有通道的综合授权」
- 点击「下一步」

**向导步骤 4 — 预览和发布**：
- 页面显示策略预览：
  - 策略名称、描述
  - 规则列表（缩略版）：优先级、名称、条件、通道、排序
  - 容错策略设置
- 按钮：「发布策略」（主操作）、「返回编辑」（次要）
- 点击「发布策略」→ 弹窗确认：「发布后将立即生效，原有策略将失效，是否继续？」
- 确认 → 策略发布成功，Modal 关闭，策略列表中新增一行，状态「已发布」，版本 1

### Step 8: 应用上线
- 应用状态变为「已发布策略，可接收支付」
- 商户获得 appid 后，可以在自己的应用中调用本平台 API 了

---

## 流程 2：终端用户首次支付（含综合授权）

### Step 1: 用户点击支付
- 用户在商户应用中，看到订单页面，点击「支付」
- 商户应用调用本平台 `/pay/order/create` 接口

### Step 2: 平台返回结果（分两种情况）

**情况 A：用户已综合授权过**
- 返回 `pay_info`（微信预支付 ID、支付宝字符串等）
- 商户应用直接唤起对应支付 SDK

**情况 B：用户未综合授权**
- 返回 `NEED_AUTHORIZATION` 状态，附带需要授权的通道列表
- 商户应用收到响应，调用弹窗组件

### Step 3: 综合授权弹窗（关键交互）

1. 弹窗叠加层出现（半透明背景，模态窗居中）
2. 弹窗标题：「完成支付方式授权」or「你需要授权以下支付方式以完成支付」
3. 弹窗正文：
   - 友好的说明文字：「为了提升支付成功率，我们准备了多种支付方式。你只需一次性授权，后续将自动为你选择最佳支付方式。」
   - 通道列表垂直展示：
     - 每个通道是一个卡片：
       - 左边：通道 Logo（大小约 48x48）
       - 中间：通道名称（粗体）、一行描述
       - 右边：开关 switch（绿色打开，灰色关闭）
     - 卡片之间有 12px 间距
   - 卡片顶部有统一的「全选」/「全不选」文字链接
4. 按钮底部：
   - 左边：「取消」文字按钮（次要）
   - 右边：「确认授权」填充按钮（主操作，绿色背景白字），按钮文字可能变成「授权中...」loading
5. 用户操作：
   - 如果用户关闭弹窗 or 点击取消 → 返回支付页，支付不继续
   - 用户打开全部开关 → 点击确认
6. 点击确认后的交互：
   - 按钮文字变为「授权中...」，按钮 disabled
   - 每个通道授权完成后，卡片有一个小对勚浮现（动画）
   - 显示进度：「正在授权 2/3 个支付方式...」
   - 全部完成 → 弹窗自动关闭（或显示「授权完成，正在跳转支付...」后自动关闭）
7. 关闭弹窗后，商户应用重新调用 `/pay/order/create`（这次用户已授权），拿到 pay_info，执行支付

### Step 4: 支付执行
- 商户应用调用微信/支付宝 SDK，用户在支付面板完成操作
- 支付成功后，微信/支付宝回调第三方 → 第三方回调本平台 → 本平台回调商户应用

### Step 5: 用户结束
- 用户看到支付成功页，流程结束
- 用户与该应用下的所有通道的授权关系已记录，无需再次授权

---

## 流程 3：通道异常时的无感切换（后台进行，用户无感）

### Step 1: 正常支付
- 用户发起支付，路由引擎选择通道 A（比如微信）
- 用户已综合授权过所有通道

### Step 2: 通道 A 失败
- 微信支付 API 返回错误 or 超时
- 路由引擎检测到通道 A 不可用

### Step 3: 自动切换到通道 B
- 路由引擎查询策略的候选通道列表，选择通道 B（比如支付宝）
- **检查用户授权**：用户已综合授权过支付宝 → 通过
- 调用支付宝支付，不告诉用户任何事情
- 用户仍然在等待中，Loading 状态可能稍微延长一点（可以显示模糊的「正在处理中...」）

### Step 4: 支付成功
- 支付宝支付成功 → 返回给商户应用 → 展示支付成功页
- 用户完全不知道中间换了通道

### Step 5: 记录绑定
- 在后台记录：这笔交易使用了通道 B
- 用户-应用-通道 B 的绑定关系更新（最近使用时间、使用次数）

---

## 流程 4：退款时的通道选择

### Step 1: 商户发起退款
- 商户应用调用 `/pay/refund`
- 传递订单号、退款金额、退款原因

### Step 2: 平台查询原交易
- 查找原支付交易记录，获取原使用的通道
- 优先使用原通道退款

### Step 3: 原通道退款执行 or 失败
- 如果原通道可用 → 调用原通道退款 API
- 如果原通道不可用 → 查找用户对其他通道的授权，尝试使用其他通道退款
- 退款成功 → 返回给商户

---

## 流程 5：新支付通道上线（平台管理员视角）

### Step 1: 开发适配器
- 工程师编写新的通道适配器类，实现统一接口
- 打包进平台的类路径（jar 包、或插件目录）

### Step 2: 管理员在平台后台注册
1. 进入「通道管理」页面
2. 点击「新增通道」
3. 输入通道编码（如 `new_channel`）、名称、适配器类路径
4. 设置支持的场景
5. 设置配置模板（JSON 编辑器，定义有哪些字段、哪些是必填、哪些加密）
6. 点击保存 → 通道状态为「已注册，未启用」

### Step 3: 启用通道
1. 在通道列表找到新通道，点击「启用」
2. 通道状态变为「启用」
3. 此时，所有已认证的商户在「选择通道」页面都能看到这个新通道了

### Step 4: 商户选择和配置
- 商户进入应用的通道管理页，看到新通道，勾选
- 配置实例（按照模板字段填写）
- 测试连通性
- 配置策略时可以选择这个新通道作为候选

# 🧠 设计决策与权衡

## 决策 1: 是否在支付界面显示通道选择？

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **不显示通道选择**（完全自动路由） | 用户体验最简洁，无需额外学习；综合授权一次搞定 | 用户感觉不到选择权 | **推荐做法**（配合策略配置让商户决定） |
| **显示通道选择** | 用户有参与感，可根据经验选择 | 增加界面复杂度；授权管理更复杂 | 根据商户需求提供开关 |

**结论**：平台提供两种模式供商户配置：
- **模式 A：自动路由模式** — 不显示通道选择，平台按策略自动路由，用户综合授权一次
- **模式 B：用户选择模式** — 显示通道选择列表，用户指定通道，平台在后台验证是否可用/已授权，否则自动 fallback

## 决策 2: 综合授权的展示方式

| 方案 | 描述 | 优势 |
|------|------|------|
| **开关列表**（当前设计） | 每个通道一个开关，用户自主选择哪些授权 | 直观、可部分授权 |
| **全选按钮 + 列表确认** | 「授权全部支付方式」一个按钮，弹窗确认 | 更简洁，适合渠道少的情况 |
| **渐进式**（进阶方案） | 只授权第一个通道，其他通道在需要时再授权（自动尝试代授权） | 最无感，但技术复杂，部分通道不支持 |

**结论**：第一版上线使用「开关列表」方案，用户可全选/部分选择。未来可以增加「一键全选」快捷选项。

## 决策 3: 通道切换时是否通知用户？

| 方案 | 描述 | 优势 | 劣势 |
|------|------|------|------|
| **完全不通知**（当前设计） | 用户无感，支付正常进行 | 最佳体验 | 如果切换频繁，用户可能疑惑 |
| **轻量提示** | 支付 loading 旁边显示「正在为你选择最佳支付方式...」 | 减少疑惑 | 增加界面元素 |
| **失败后通知** | 第一个通道失败后才提示用户 | 透明 | 体验中断 |

**结论**：第一版采用「完全不通知」，后续可根据用户反馈增加轻量提示（如「正在为你选择最佳支付方式...」文案在 loading 旁）。

## 决策 4: 策略规则的优先级管理

- **拖拽排序**：用户可以通过拖拽规则卡片调整优先级，直观方便
- **数字输入**：也可以手动输入优先级数字
- **自动排序**：新添加的规则默认放在最后，用户手动调整
- **规则数量限制**：建议最多 10 条规则，避免过于复杂

# 🎁 可供参考的组件交互细节

## 综合授权弹窗 — 详细交互

```
┌─────────────────────────────────────────────────────┐
│ ✕                                                  │
│                                                     │
│     完成支付方式授权                                │
│                                                     │
│     为了提升支付成功率，我们准备了多种支付方式。     │
│     你只需一次性授权，后续将自动为你选择最佳支付方式。 │
│                                                     │
│     ┌─────────────────────────────────────────┐     │
│     │ 全部选择 ✅                    全不选 ❌ │     │
│     ├─────────────────────────────────────────┤     │
│     │                                             │     │
│     │   [微信图标]    设置开关    微信支付       │     │
│     │              ├───●───────              │     │
│     │              电商、APP场景支付              │     │
│     │                                             │     │
│     │   [支付宝图标]  设置开关    支付宝支付      │     │
│     │              ├───●───────              │     │
│     │              电商、H5场景支付              │     │
│     │                                             │     │
│     │   [中金图标]    设置开关    中金支付       │     │
│     │              ├───●───────              │     │
│     │              综合支付方案、大额支付          │     │
│     │                                             │     │
│     └─────────────────────────────────────────┘     │
│                                                     │
│                      [取消]  [确认授权]              │
└─────────────────────────────────────────────────────┘
```

**交互时序**：
1. 弹窗出现，所有开关初始状态根据后端返回（可能全都是关闭的）
2. 用户切换开关，实时反馈
3. 用户点击「确认授权」：
   - 如果至少选了一个 → 按钮 loading，「授权中...」
   - 如果一个都没选 → 按钮 disabled，提示「请至少选择一个支付方式」
4. 授权过程中：
   - 按顺序授权每个选中的通道
   - 每成功一个，对应卡片的开关变成绿色 AND 右侧出现小对勚动画
   - 底部按钮文字实时更新：「正在授权 1/3...」「正在授权 2/3...」
5. 全部成功：
   - 弹窗自动关闭（或显示「授权完成」1 秒后关闭）
   - 商户应用收到回调，继续支付流程
6. 部分成功（某个通道授权失败）：
   - 失败的卡片开关变成灰色，显示错误图标
   - 弹窗不自动关闭，显示提示：「微信支付和支付宝授权成功，中金支付授权失败。是否继续支付？」
   - 按钮更新为：「跳过失败的通道，继续支付」or「重新授权」
