# 用例模型 (Use Case)

## 角色 (Actors)

| 角色 | 类型 | 描述 |
|------|------|------|
| **商户管理员** | Primary | 商户的管理人员，负责在平台创建应用、配置通道、策略等 |
| **终端用户** | Primary | 消费者/付款方，通过商户应用发起支付 |
| **平台管理员** | Secondary | 支付平台的运营人员，负责审核商户、管理通道、监控系统 |
| **支付通道** | Secondary | 第三方支付服务商（微信、支付宝、中金、宝付等），作为外部系统参与 |

## 用例列表

### UC-1: 商户注册与认证

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-1 |
| 用例名称 | 商户注册与认证 |
| 参与者 | 商户管理员 |
| 前置条件 | 无 |
| 后置条件 | 商户账户创建完成，等待实名认证 |

**主流程**：
1. 商户管理员访问平台注册页面
2. 输入商户基本信息（公司名称、统一社会信用代码、联系方式等）
3. 提交注册申请
4. 系统创建商户账户，生成商户 ID
5. 系统发送认证材料清单给商户
6. 商户上传认证材料（营业执照、法人身份证等）
7. 平台审核材料
8. 审核通过 → 商户获得完整账户权限
9. 审核不通过 → 反馈原因，商户可修正后重新提交

**扩展流程**：
- 3a. 信息校验失败：提示具体错误，商户修正后重新提交

### UC-2: 创建应用

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-2 |
| 用例名称 | 创建支付应用 |
| 参与者 | 商户管理员 |
| 前置条件 | 商户已完成注册和认证 |
| 后置条件 | 应用创建成功，获得 appid |

**主流程**：
1. 商户管理员登录商户后台
2. 进入「应用管理」页面
3. 点击「创建应用」
4. 输入应用信息（应用名称、应用类型、回调地址等）
5. 提交创建申请
6. 系统为应用生成唯一 `appid`
7. 系统显示应用详情页，包含 appid 和状态

**扩展流程**：
- 4a. 应用名称重复：提示已存在，要求更换名称

### UC-3: 选择支付通道

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-3 |
| 用例名称 | 选择支付通道 |
| 参与者 | 商户管理员 |
| 前置条件 | 应用已创建 |
| 后置条件 | 选中的通道被关联到应用， awaiting 配置 |

**主流程**：
1. 商户管理员进入应用的「支付通道」管理页
2. 系统显示可用支付通道列表（微信、支付宝、中金、宝付等）
3. 商户勾选需要接入的通道
4. 提交选择
5. 系统将选中的通道与应用关联，状态设为「未配置」

**扩展流程**：
- 3a. 部分通道不可用（已停用或未签约）：高亮提示，无法勾选

### UC-4: 配置渠道实例

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-4 |
| 用例名称 | 配置渠道实例 |
| 参与者 | 商户管理员 |
| 前置条件 | 通道已选择，状态为「未配置」 |
| 后置条件 | 渠道实例配置完成，状态为「已配置」或「待测试」 |

**主流程**：
1. 商户管理员点击待配置的通道
2. 系统显示该通道的配置表单（根据通道类型动态生成）
3. 商户填写配置参数：
   - 第三方商户号（mch_id）
   - 秘钥/证书（key、cert）
   - 费率设置
   - 额度限制
   - 场景适用范围
   - 回调地址
4. 提交配置
5. 系统保存配置，加密敏感信息
6. 系统提示「配置已保存，建议测试连通性」

**扩展流程**：
- 3a. 必填项未填：表单校验提示，禁止提交
- 3b. 参数格式错误（如费率 >1）：实时校验提示

---

### UC-5: 测试渠道连通性

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-5 |
| 用例名称 | 测试渠道连通性 |
| 参与者 | 商户管理员 |
| 前置条件 | 渠道实例配置完成 |
| 后置条件 | 连通性测试结果记录 |

**主流程**：
1. 商户管理员点击「测试连通性」按钮
2. 系统使用配置的参数调用第三方通道的测试 API（如微信的证书校验、支付宝的签名验证）
3. 通道响应成功 → 系统标记为「连通正常」
4. 通道响应失败 → 系统显示错误信息，标记为「连通异常」

### UC-6: 配置支付策略

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-6 |
| 用例名称 | 配置支付策略 |
| 参与者 | 商户管理员 |
| 前置条件 | 至少有一个渠道实例已配置完成 |
| 后置条件 | 策略发布生效 |

**主流程**：
1. 商户管理员进入应用的「支付策略」配置页
2. 系统显示已有策略列表（可有多个策略）
3. 点击「新建策略」
4. 输入策略名称、描述
5. 添加策略规则（可添加多条规则）：
   - 设置规则优先级（priority）
   - 设置条件（金额区间、场景、地域、设备类型、风控等级）
   - 设置候选通道列表（从已配置通道中选择）
   - 设置排序方式（费率升序、额度优先等）
6. 配置容错策略：
   - 是否启用自动容错
   - 最大尝试次数
   - 是否需要重新授权
7. 保存策略（草稿状态）
8. 预览策略
9. 发布策略 → 策略生效，旧策略自动失效

**扩展流程**：
- 5a. 候选通道为空：禁止发布，提示至少选择一个通道
- 5b. 规则优先级冲突：提示冲突，要求调整

---

### UC-7: 终端用户发起支付

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-7 |
| 用例名称 | 终端用户发起支付 |
| 参与者 | 终端用户 |
| 前置条件 | 商户应用已上线，策略已发布 |
| 后置条件 | 支付订单创建，路由到具体通道执行 |

**主流程**：
1. 终端用户在商户应用中选择商品/服务
2. 用户点击「支付」
3. 商户应用调用本平台支付 API 创建订单
4. 本平台路由引擎根据策略选择最佳通道 A
5. 本平台检查用户是否已对通道 A 授权
6. 若已授权 → 返回给商户应用，准备调用通道 A
7. 若未授权 → 返回给商户应用，提示需要授权

**扩展流程**：
- 5a. 用户未授权：进入 UC-8 综合授权流程

---

### UC-8: 综合授权（一次性多通道授权）

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-8 |
| 用例名称 | 综合授权 |
| 参与者 | 终端用户 |
| 前置条件 | 用户未对某些候选通道授权 |
| 后置条件 | 用户对应用下所有候选通道完成授权 |

**主流程**：
1. 商户应用收到需要授权的响应
2. 商户应用弹出综合授权界面
3. 界面列出该应用已配置的所有支付通道（微信、支付宝、中金、宝付等）
4. 终端用户确认授权（可全选/部分选择）
5. 商户应用调用本平台授权 API，传递用户的授权选择
6. 本平台依次向各通道请求授权（或通过平台预存授权）
7. 各通道返回授权结果
8. 本平台记录各通道的授权状态和凭证
9. 本平台返回授权完成给商户应用
10. 商户应用继续执行支付流程

**扩展流程**：
- 4a. 用户拒绝部分通道：记录拒绝状态，该通道不参与后续路由
- 6a. 部分通道授权失败：记录失败状态，可提示用户稍后重试

---

### UC-9: 支付执行（调用具体通道）

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-9 |
| 用例名称 | 支付执行 |
| 参与者 | 本平台（路由引擎）、支付通道、终端用户 |
| 前置条件 | 订单已创建，通道已选定，用户已授权 |
| 后置条件 | 支付结果返回给商户应用 |

**主流程**：
1. 路由引擎调用选定通道 A 的适配器
2. 适配器构建第三方请求参数
3. 适配器调用第三方支付 API
4. 第三方返回支付结果（同步或异步）
5. 适配器解析结果，记录交易日志
6. 路由引擎将结果返回给商户应用

**扩展流程**：
- 4a. 第三方 API 超时/异常：适配器重试（可配置次数），仍失败则触发容错流程（UC-10）

---

### UC-10: 通道故障容错（动态切换）

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-10 |
| 用例名称 | 通道故障容错 |
| 参与者 | 路由引擎、终端用户 |
| 前置条件 | 当前通道支付失败/不可用 |
| 后置条件 | 切换到备用通道继续支付，或支付失败 |

**主流程**：
1. 路由引擎检测到通道 A 支付失败（API异常、超时、返回错误码等）
2. 路由引擎查询策略的候选通道列表，获取下一个备选通道 B
3. 路由引擎检查用户是否已对通道 B 授权
4. 若已授权（综合授权已涵盖） → 无感切换，继续 UC-9 执行通道 B 支付
5. 若未授权 → 根据 `fallback_policy` 判断：
   - 若 `require_re_authorization: false` 且平台能代授权 → 尝试代授权
   - 若需要用户授权 → 返回给商户应用，提示用户授权 B
6. 用户授权 B 后，继续执行 UC-9 支付通道 B
7. 若所有候选通道均失败 → 返回支付失败给商户应用

**扩展流程**：
- 2a. 无其他候选通道：直接返回支付失败
- 5a. 用户拒绝重新授权：返回支付失败

---

### UC-11: 支付结果查询

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-11 |
| 用例名称 | 支付结果查询 |
| 参与者 | 商户应用（或终端用户） |
| 前置条件 | 支付订单已创建 |
| 后置条件 | 返回订单支付状态 |

**主流程**：
1. 商户应用调用本平台查询 API，传递订单号
2. 本平台查询本地交易记录
3. 返回当前状态（待支付、支付中、支付成功、支付失败等）

### UC-12: 退款

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-12 |
| 用例名称 | 退款 |
| 参与者 | 商户管理员 / 商户应用 |
| 前置条件 | 原始交易支付成功 |
| 后置条件 | 退款处理完成 |

**主流程**：
1. 商户发起退款请求（订单号、退款金额、原因）
2. 本平台查询原始交易记录，获取原始支付通道
3. 本平台优先调用原始通道的退款 API
4. 原始通道退款成功 → 记录退款完成，返回成功
5. 原始通道退款失败（不可用/不支持） → 尝试其他已授权通道的退款
6. 若所有通道退款均失败 → 返回退款失败

**扩展流程**：
- 5a. 跨通道退款不被支持：记录失败原因，提示商户需联系原始通道处理

### UC-13: 对账（Reconciliation）

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-13 |
| 用例名称 | 对账 |
| 参与者 | 平台管理员 / 商户管理员 |
| 前置条件 | 有交易记录 |
| 后置条件 | 生成对账报告 |

**主流程**：
1. 系统/商户触发对账请求
2. 系统遍历指定时间范围内的所有交易记录
3. 对每笔交易，调用对应第三方通道的查询 API
4. 比较本平台记录与第三方记录
5. 一致 → 标记对账成功
6. 不一致 → 记录差异详情，生成差异报告
7. 汇总所有结果，生成对账报告
8. 推送报告给商户

---

### UC-14: 回调处理

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-14 |
| 用例名称 | 回调通知处理 |
| 参与者 | 支付通道（外部系统）、本平台 |
| 前置条件 | 某笔订单状态发生变化 |
| 后置条件 | 本平台交易记录更新，商户收到回调 |

**主流程**：
1. 第三方通道向本平台规定的回调地址发送 HTTP 请求
2. 本平台回调接收服务接收请求
3. 验证回调签名（确保是第三方发送的）
4. 解析回调参数，更新交易记录状态
5. 根据商户配置，向商户的回调地址转发通知（可选）
6. 返回成功应答给第三方通道

---

### UC-15: 新支付通道接入（配置化）

| 属性 | 内容 |
|------|------|
| 用例编号 | UC-15 |
| 用例名称 | 新支付通道接入 |
| 参与者 | 平台管理员 / 开发人员 |
| 前置条件 | 有新的第三方支付通道需要接入 |
| 后置条件 | 新通道可以在平台上配置和使用 |

**主流程**：
1. 开发人员编写新的通道适配器实现类（实现 `IPaymentChannel` 接口）
2. 将适配器打包成 JAR 或放入类路径
3. 平台管理员在后台「通道管理」中添加新通道：
   - 输入通道编码、名称
   - 选择适配器类
   - 设置默认配置模板
4. 保存后，新通道出现在可用通道列表中
5. 商户可在应用中选择该新通道（UC-3）
6. 商户配置该通道实例（UC-4）
7. 测试连通性（UC-5）

**扩展流程**：
- 3a. 适配器未找到：提示类路径问题，无法添加

## 用例之间的关系

```
UC-1 注册认证 ──> UC-2 创建应用
UC-2 创建应用 ──> UC-3 选择通道
UC-3 选择通道 ──> UC-4 配置实例
UC-4 配置实例 ──> UC-5 测试连通性
UC-4 配置实例 ──> UC-6 配置策略
UC-6 配置策略 ──> UC-7 发起支付
UC-7 发起支付 ──> UC-8 综合授权（可选）
UC-7/8 ──> UC-9 支付执行
UC-9 支付执行 ──> UC-10 容错切换（异常时）
UC-9 支付执行 ──> UC-11 查询结果
UC-7/11 ──> UC-12 退款
UC-9/12 ──> UC-14 回调处理
UC-13 对账 ──< 独立流程
UC-15 新通道接入 ──< 平台侧配置流程
```
